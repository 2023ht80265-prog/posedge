01 · BASICS

APB in three lines

Start with the three signals that run every transfer. Then see where APB sits in a chip and why it is built so simply.

PSEL says who.The requester selects one completer and puts the address on the bus.

PENABLE says now.One cycle later, it starts the access.

PREADY says done.The completer finishes when it is ready.

At the clock edge where all three are high, the transfer happens. This page calls it the triple-high edge. That one sentence is most of APB.

Try it now · move across this waveform: a write with one wait state, then a read

Where APB sits

A CPU talks to memory over a fast, pipelined bus such as AXI or AHB. Peripheral registers do not need that speed. An APB bridge converts each fast-bus access into one APB transfer and acts as the only requester on the APB side. Each peripheral is a completer with its own select line, PSELx. Address, write data and control wires are shared.

AMBA 5 documents use Requester and Completer. Older documents and most existing RTL say master and slave. They mean the same roles.

Every transfer has two phases. In SETUP the requester raises PSELx and puts address, direction and write data on the bus. One cycle later it raises PENABLE for ACCESS. From APB3 onward the completer can stretch ACCESS by holding PREADY low. The transfer completes at the rising edge where PSEL, PENABLE and PREADY are all high.

That is the whole protocol. The rest is detail about what must stay stable, what is sampled when, and what each later version added.

Why it's cheapNo pipelining, no bursts, no IDs, no outstanding transactions, one requester. A completer can be a register bank plus three gates of decode logic.
Why it's slowEach transfer takes at least two cycles, so peak throughput is one transfer every two cycles. Wait states lower that further.
TimingEverything is synchronous to the rising edge of PCLK. In these waveforms, cycle n is sampled at edge Tn+1.

03 · STATE MACHINE

Three states drive everything

    Reading the diagram

    • IDLE is the default. The bus stays here while nothing is requested.
    • SETUP lasts exactly one cycle, always. There is no condition on the SETUP → ACCESS arc.
    • ACCESS repeats while PREADY is low. Each repeat is a wait state.
    • From a completing ACCESS the bus goes straight to SETUP if another transfer is pending. That is a back-to-back transfer: PSEL stays high and only PENABLE drops.

          APB5AMBA 5 · 2021 →

          APB2

          AMBA 2 APB
          Signals: PCLKPRESETnPSELxPENABLEPADDRPWRITEPWDATAPRDATA

          There is no PREADY, so every transfer is exactly one SETUP cycle and one ACCESS cycle. A completer that is slow has no way to say so: it must answer within that ACCESS cycle. There is no error signal either.

          APB3

          AMBA 3 APB v1.0
          Adds: PREADYPSLVERR

          The completer holds PREADY low to insert wait states, and drives PSLVERR high in the completing cycle to report an error. An APB2 completer works on an APB3 bus with PREADY tied high and PSLVERR tied low. The waveform shows a write with one wait state that fails, then a read that fails.

          APB4

          AMBA APB v2.0
          Adds: PPROT[2:0]PSTRB[DATA/8-1:0]

          PPROT carries privileged / non-secure / instruction attributes so a completer can filter accesses. PSTRB allows sparse writes: only byte lanes with a strobe bit set are updated, and PSTRB must be all zeros on reads. Here a write updates only the low two bytes, then the read returns the merged word.

          Interop trapAn APB3 completer has no PSTRB input. If an APB4 requester sends a partial write to it, the completer writes the full word and corrupts the bytes that should have been left alone. The interconnect must block, error, or emulate those writes.

          APB5

          AMBA 5 APB, Issue D onward
          Adds: PWAKEUPPAUSERPWUSERPRUSERPBUSER*CHK parityPNSE (RME)

          PWAKEUP tells a clock-gated or power-gated completer that activity is coming, so it can wake before PSEL. User signals carry implementation-defined sideband data with the same timing as the signal they accompany. The optional check signals add odd parity for functional-safety designs. The waveform shows PWAKEUP leading PSEL by two cycles.

          07 · CORNER CASES

          Where APB designs actually break

          Every item here has caught a real bug somewhere. Each card says why it matters and how to hit it in a testbench. Several are loadable presets in the lab.

          Timing and flow

          Zero wait states

          The fastest case: SETUP then one ACCESS. Completers that need a cycle to decode often have bugs only here.

          Hit itForce or tie PREADY high; weight wait_cycles == 0 heavily.

          Long stalls

          A completer holds PREADY low for many cycles. APB has no timeout, so the bridge or the CPU hangs unless something watches.

          Hit itRandomise 0 to 16+ waits; add a bounded-completion assertion and a bridge watchdog test.

          PREADY high during SETUP

          Legal, and must be ignored. A completer that defaults PREADY high is common. A requester that completes on it is broken.

          Hit itCompleter model option that drives PREADY=1 when idle. Lab preset: PREADY high during SETUP.

          Back-to-back, same completer

          PSEL never falls; only PENABLE pulses low. Completers that use PSEL's falling edge to finish an operation miss the second transfer.

          Hit itidle_cycles == 0 sequences; cover done ##1 setup.

          Back-to-back, different completers

          PSEL1 falls in the same cycle PSEL2 rises. The read mux in the bridge must switch cleanly.

          Hit itAlternate target regions with zero idle cycles. Lab preset: two peripherals.

          Read immediately after write

          Back-to-back read of the address just written. Exposes write pipelines that update a cycle late.

          Hit itDirected W→R pairs to the same address with 0 waits.

          Responses

          PSLVERR on a write

          The register may or may not have been updated. A scoreboard that assumes either way will produce false failures.

          Hit itError-injecting completer model; scoreboard marks the location unknown.

          PSLVERR on a read

          PRDATA is not guaranteed valid. The requester must not forward it as good data.

          Hit itReturn garbage with PSLVERR=1 and check the bridge's response to the fast bus.

          Error after wait states

          PSLVERR is only meaningful on the final cycle. A requester sampling it on every ACCESS cycle sees noise.

          Hit itCross wait_cycles with slverr in coverage.

          Unmapped address

          An address inside the APB region but outside any completer. Something must still answer, or the bus hangs.

          Hit it10% of addresses outside the map; expect a default completer with PSLVERR or read-as-zero, per your design spec.

          Data and strobes

          Write with PSTRB = 0000

          Legal in APB4. No bytes change. Completers that ignore strobes write anyway.

          Hit itKeep 0 in the strobe distribution; check the register is unchanged.

          Sparse strobes

          Single bytes, half-words and patterns like 0101. Byte-enable logic often handles 1111 and nothing else.

          Hit itCoverpoint bins for each single lane, both halves, and others.

          Partial write to an APB3 completer

          No PSTRB input, so it writes the whole word. See the APB4 interop trap.

          Hit itSystem-level test through the real interconnect, not just block level.

          Unaligned address

          PADDR low bits not zero. Behaviour is design-specific: aligned-down, error, or ignored.

          Hit itTurn off the alignment constraint in one test; check against the register spec.

          Reset, power, protection

          Reset in the middle of a transfer

          Both sides must return to IDLE. The requester must not complete the old transfer after reset deasserts.

          Hit itAssert PRESETn at a random cycle during ACCESS; restart traffic.

          First transfer after reset

          The very first cycle after release. Exposes state that is not initialised by reset.

          Hit itLab preset: Reset, then the first transfer.

          Wake from clock gating (APB5)

          A transfer starts right after PWAKEUP rises. The completer's clock must be running by SETUP.

          Hit itVary PWAKEUP lead from 0 to several cycles.

          Protection mismatch

          Non-secure access to a secure register, unprivileged access to a privileged one. Expect PSLVERR or read-as-zero, write-ignored.

          Hit itCross PPROT with register address in coverage.

          Parity error injection (APB5)

          Flip one bit on a protected signal or its check bit. The receiver must flag it.

          Hit itError-injection callbacks in driver and completer model.

          08 · COMMON BUGS

          Bugs you will meet, and what catches them

          Design bugs first, then testbench bugs. Testbench bugs are worth as much attention: they either hide design bugs or waste days on false failures.

          In the design

          Bug

          Write happens in SETUP

          Completer decodes PSEL && PWRITE without PENABLE.
          SymptomRegister updates a cycle early. With wait states, a FIFO push or write-to-clear fires on every cycle of the transfer.
          Caught byScoreboard with randomised waits; FIFO level checks. Fix: qualify with PSEL && PENABLE && PREADY.
          Bug

          Read side effect repeats

          Read-to-clear status or FIFO pop on every ACCESS cycle, not just the completing one.
          SymptomLost FIFO entries or cleared flags whenever the read has wait states.
          Caught byReads with wait states to side-effect registers, compared against a reference model.
          Bug

          Wait counter not reset at completion

          Counter only resets on PSEL low.
          SymptomBack-to-back transfers get the wrong number of wait states, so data is sampled early.
          Caught byBack-to-back sequences plus a monitor that records wait_cycles.
          Bug

          PSTRB ignored

          Completer writes all four bytes regardless of strobes.
          SymptomNeighbouring bytes corrupted by partial writes.
          Caught byStrobe coverage plus a byte-accurate register model.
          Bug

          PRDATA driven when not selected

          Completer drives its register value onto PRDATA at all times.
          SymptomBridges that OR the PRDATA of all completers return corrupted read data.
          Caught byReads to one completer while another holds non-zero data; a check that PRDATA is zero when PSEL is low, if the design spec requires it.
          Bug

          Bridge changes PADDR in a wait state

          Bridge forwards the next fast-bus address while APB is still waiting.
          SymptomThe completer acts on the wrong register.
          Caught bya_stable_ctrl, with completers that insert waits.
          Bug

          Incomplete address decode

          Completer compares only low address bits.
          SymptomRegisters alias across the region; writes to one offset change another.
          Caught byWalking-ones address test and aliasing checks in the register model.

          In the testbench

          Bug

          Monitor samples on PENABLE

          Transaction captured when PSEL and PENABLE are high, ignoring PREADY.
          SymptomDuplicate or garbage transactions for every wait state.
          FixCapture only when PSEL, PENABLE and PREADY are all high.
          Bug

          Driver waits a fixed cycle

          Driver drops PSEL after one ACCESS cycle.
          SymptomPasses against zero-wait completers, breaks the protocol against any completer with waits.
          FixLoop on PREADY. Exercise E8 walks through it.
          Bug

          Race with the DUT

          Driver uses blocking assignments at posedge without a clocking block.
          SymptomResults change with simulator or event ordering.
          FixDrive and sample through clocking blocks.
          Bug

          Comparing PRDATA on errors

          Scoreboard checks read data even when PSLVERR is high.
          SymptomFalse failures on every error test.
          FixSkip or special-case the comparison on errors.
          Bug

          Illegal stimulus

          Sequence item lacks dir == READ -> strb == 0.
          SymptomChecker fires on stimulus, and the team weakens the checker to make it pass.
          FixConstrain the item. Never relax a correct checker to suit a wrong testbench.
          Bug

          Assertions active in reset

          No disable iff.
          SymptomA flood of failures at time zero that people learn to ignore.
          FixDefault disable on reset; a separate reset-state check.
          09 · ASSERTIONS

          A complete SVA protocol checker

          Bind this to any APB completer interface. It holds every assertion the lab runs (chapter 06 lists them), and the cover properties tell you whether your stimulus reached the interesting cases. Want to see one fire? Each golden rule in chapter 06 has a See it break button, and the lab's Build your own tab lets you write and score your own.

          Gotchas that cost interview points

          • |-> checks the consequent in the same cycle; |=> checks it one cycle later. "SETUP is followed by ACCESS" needs |=>.
          • $stable(x) compares the current sample to the previous one. Put it after |=> with SETUP or a wait state as the antecedent, so it checks each step of the transfer.
          • $past and $rose look one sampled clock back. Right after reset release that value may come from the reset period.
          • The reset check needs its own disable iff (1'b0), otherwise the default disable switches it off exactly when it should run.

          Why some checks are warnings

          a_err_only_on_done encodes a recommendation: the specification asks completers to drive PSLVERR low outside completion but does not require it. Making it an error would fail legal designs.

          a_max_wait is a liveness proxy. APB allows unbounded wait states, so the bound is testbench policy. In formal, prefer a real liveness property with fairness assumptions on the completer.

          10 · CONSTRAINTS

          Stimulus that is legal by construction

          The sequence item carries both requester-side fields (address, data, strobes, protection, idle gap) and completer-side fields (wait states, error) so one item drives a requester agent or a reactive completer agent.

          Design choices worth defending

          • Constrain protocol rules, weight corner cases. c_strb_read is a hard rule. Everything else is a distribution, so legal corners like strb == 0 still appear.
          • := vs :/. := gives the weight to every value in a range; :/ splits it across the range. [1:3] :/ 35 means 35 in total, not 105.
          • solve dir before strb keeps the direction split near 50/50. Without it, the many strobe values on writes pull the solver toward writes.
          • Turn constraints off by name with constraint_mode(0) for one corner test, rather than weakening the base class.
          • Redeclaring a constraint with the same name in a subclass replaces the parent's version. That is how a test-specific item changes the address range.

          Written exercises

          E1

          Assert that PWDATA is stable during a write

          Basic

          Write a property that fails if PWDATA changes at any point between SETUP and the completing cycle of a write. Do not use the helper wires from chapter 09.

          Hint

          The antecedent is "SETUP or wait state, and it is a write". Use |=> and $stable.

          Solution
          E2

          Bounded completion

          Basic

          Assert that every transfer completes within 8 cycles of its SETUP cycle. Then explain why this is a testbench policy and not an APB rule.

          Solution

          The earliest completion is one cycle after SETUP, hence ##[1:8]. APB places no limit on wait states, so this bound comes from your system requirements (for example, the CPU's bus timeout). In formal verification, a fixed bound can also hide a real deadlock beyond it.

          E3

          Read-after-write constraint

          Intermediate

          Write constraints for a block of six transfers where every read targets an address that some earlier transfer in the block wrote.

          Hint

          The first transfer must be a write. Array reduction with item.index can express "exists an earlier j".

          E6

          Debug this completer

          Intermediate

          This completer passed all zero-wait tests. With 2 wait states, every write to the FIFO register pushes four entries. Find the bug.

          Solution

          The condition ignores PENABLE and PREADY, so it is true at the end of every cycle in which PSEL is high: 1 SETUP + 2 wait states + 1 completing cycle = 4 pushes. With zero waits it still pushes twice, but a test that only checks the last value written to a plain register never notices. Writes must happen only on the completing edge:

          Lesson for the testbench: randomise wait states from day one, or this class of bug stays hidden.

          E7

          Cycle counting

          Basic

          Eight back-to-back transfers have wait states [0, 1, 0, 2, 0, 0, 3, 0]. How many PCLK cycles do they take, and what fraction of cycles complete a transfer?

          Solution

          Each transfer is 2 + waits cycles: 8 × 2 + (0+1+0+2+0+0+3+0) = 16 + 6 = 22 cycles. Eight completions in 22 cycles is about 36%, against the zero-wait best case of 50%.

          E8

          Debug this driver

          Advanced

          Find every problem in this driver task.

          Solution
          • No loop on PREADY: it leaves ACCESS after one cycle, breaking WAIT_HOLD with any completer that inserts waits, and samples PRDATA before it is valid.
          • Blocking assignments straight to the interface at the clock edge race with the DUT. Use a clocking block and <=.
          • PSEL is always dropped, so back-to-back transfers are never generated.
          • PSTRB and PPROT are never driven (X on an APB4 bus), and PSLVERR is never captured.

          Compare with apb_master_driver in chapter 12.

          APB4 requester, APB3 completer

          Advanced

          You are designing the adapter between an APB4 requester and an APB3 completer. What do you do with a write where PSTRB is not all ones? Give two options and their costs, and the test you would write for each.

          Discussion
          • Reject: answer with PSLVERR without forwarding the write. Cheap and safe; software must avoid sub-word writes to that completer. Test: partial write returns error and the register is unchanged.
          • Read-modify-write: read the word, merge the strobed bytes, write it back. Transparent to software, but two transfers, not atomic, and wrong for registers with read side effects. Test: partial writes preserve the other bytes; read-to-clear registers are excluded.
          • Passing it through unchanged is the bug from chapter 05's interop trap.
